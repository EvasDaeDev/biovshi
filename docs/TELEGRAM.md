# Telegram Mini App

Одна веб-сборка запускается в браузере и в Telegram. Игровая логика, дизайн,
экономика и формат сохранений не меняются. Сервер и Telegram-авторизация не нужны.

## Тестовый запуск

[Тестовая игра](https://evasdaedev.github.io/biovshi/test/) публикуется из
`test/combat-hit-sync` с `--mode test`. [Основная игра](https://evasdaedev.github.io/biovshi/)
собирается из `main`. Тестовый канал использует отдельные ключи
`biovshi.test.*` и базу IndexedDB. Telegram использует хранилище текущего
канала внутри своего WebView. [Проверка коммита выпуска](https://evasdaedev.github.io/biovshi/test/build-info.json).

В BotFather выберите тестового бота → Bot Settings → Configure Mini App и задайте
этот HTTPS URL для Main Mini App. Можно также настроить Menu Button на тот же URL.
Запускайте через кнопку Mini App бота: обычная ссылка в чате может открыться как
сайт, без Telegram WebApp API. Токен бота не требуется в исходниках игры.

## Интеграция

- `index.html` загружает официальный SDK асинхронно только при наличии параметров
  запуска Telegram. Используется неизменённая локальная копия
  `public/vendor/telegram-web-app-65.js`, обслуживаемая с того же origin, что игра.
  Источник и SHA-256 зафиксированы в соседнем JSON. Запрос к telegram.org при
  запуске не нужен; CSP разрешает скрипты только с собственного origin.
  Ошибка загрузки не блокирует игру, попадает в диагностику и допускает повтор
  через кнопку «На весь экран».
- `src/platform/telegram.js` определяет платформу, проверяет версии методов,
  вызывает `expand`, `ready`, запрашивает fullscreen и отключает конфликтующие
  вертикальные жесты. Запрос fullscreen повторяется после готовности и при первом
  нажатии, пока клиент не подтвердит переход. Сохранённое SDK значение fullscreen
  не считается подтверждением: учитываются свежий fullscreenChanged и ответ
  ALREADY_FULLSCREEN. После подтверждения берётся фактическая высота WebView,
  а не оставшаяся высота прежнего окна. Шапка и фон Telegram получают цвет
  игры; отказ fullscreen оставляет обычное окно работоспособным.
- Ориентация фиксируется только после перехода в landscape: Telegram
  `lockOrientation()` фиксирует текущую ориентацию, а не поворачивает устройство.
  В portrait остаётся существующее окно «Поверните устройство».
- Системные и контентные отступы применяются до масштабирования. Для системного
  отступа берётся максимум Telegram API и CSS `env(safe-area-inset-*)`: iOS может
  сначала отдавать нули через SDK. После поворота стороны пересчитываются. При
  недоступном SDK отступы iOS сохраняются для URL запуска Telegram. Если мобильный
  fullscreen сообщает нулевой верхний content inset, резервируется строка 56 CSS
  px под системные кнопки; при получении ненулевого значения используется API. Учтены обычная
  и развёрнутая арены, джойстик, окна, подсказки, обучение и формы над клавиатурой.
- Страница Telegram фиксирована в пределах WebView, без прокрутки и резинового
  отскока документа. У джойстика есть непассивные touch-обработчики, отменяющие
  нативное перемещение. Формы и списки продолжают прокручиваться независимо.
  Запрет вертикальных жестов Telegram повторяется после fullscreen и активации.
- `appInactive` отделён от пользовательской паузы. Видимость документа, pagehide /
  pageshow и Telegram activated / deactivated останавливают симуляцию, появление
  пациентов, ввод и звук. При возвращении кадровый долг сбрасывается.
- Обработчики удаляются вместе с игровым представлением. Поздняя загрузка SDK
  подключается к текущему представлению, без повторных подписок.
- Автономная сборка `npm run standalone` удаляет загрузчик SDK и остаётся офлайн.

## Сохранения

Используются прежние localStorage и IndexedDB. Общий прогресс между отдельным
браузером и WebView Telegram не предполагается. После выгрузки WebView
восстанавливаются только существующие сохраняемые данные, а не полный снимок боя.
Прерванный бой обрабатывается по прежним правилам. Данные могут быть потеряны при
очистке локального хранилища клиентом или пользователем.

## Проверки

Автотесты: `node --test tests/telegram.test.js tests/audio.test.js tests/keyboard-viewport.test.js`.
Общая проверка: `npm test`, `npm run build -- --mode test`, `npm run standalone`.

Перед признанием поддержки клиента проверять на настоящих Android, iOS и Desktop:

1. Открыть Mini App через бота; пройти стартовый экран, настройки и обучение.
2. Запустить вертикально; повернуть горизонтально. Проверить вырезы, системные
   кнопки Telegram, обычную и развёрнутую арену. Отказ fullscreen не мешает игре.
3. Пройти Башню с джойстиком и управлением по точке. Проверить высоту Убежища,
   прокрутку модификаторов и доступность кнопок под складом. Повторить переходы
   между Башней, тотализатором, процедурной и итогами.
4. Во время боя свернуть Mini App на 15–30 секунд. Вернуться: время и состояние
   боя не перескочили, ввод отпущен. Повторить с заранее установленной паузой.
5. Открыть клавиатуру в форме: масштаб арены не меняется, поле доступно.
6. Изменить сохраняемые данные (например, имя игрока), закрыть Mini App полностью
   и открыть вновь. Проверить сохранение; отдельно проверить штатную обработку
   прерванного боя. Повторить после перезапуска клиента Telegram.
7. В обычном браузере проверить тот же URL; основная версия должна работать без
   Telegram. В старом клиенте отсутствие fullscreen / safe area API не мешает старту.

Официальная документация: https://core.telegram.org/bots/webapps

## Диагностика на устройстве

В настройках Mini App есть раздел «Telegram: экран и отступы». Кнопка «На весь
экран» повторяет запрос независимо от кешированного флага SDK. «Скопировать
диагностику» копирует номер сборки и исходный коммит, состояние и ошибку fullscreen,
размеры окна и visualViewport, отступы Telegram, рассчитанные отступы и положение
игры. Данные авторизации и профиль пользователя в отчёт не включаются.

В Telegram убрана обычная рамка веб-страницы 12px: остаются системные отступы и
отступ под кнопки клиента. Браузерный запуск сохраняет прежнюю рамку. Нельзя
надёжно определять безопасную сторону по расположению камеры: используются
значения текущего WebView, которые на отдельных устройствах защищают обе стороны.

Тест `tests/telegram-sdk.test.js` загружает настоящий SDK через HTML-загрузчик,
запрещая сеть за пределами смоделированного origin игры. Он проверяет оба пути
GitHub Pages, инициализацию iOS API, отправку fullscreen и получение safe-area
событий. Перед публикацией также проверяется наличие SDK в артефакте и его SHA-256.
