# Тестовые бои Башни — 17 ноября 2026

**Ветка:** `experiment/tower-bosses` (без публикации и переноса в `main`).  
**Метод:** автоматические headless-бои внутри настоящего игрового цикла `step(1/60)` (JS DOM). Используются текущие столкновения, враги, повреждения, атаки и ИИ, **не** математическая имитация исходов. Игроком управляет простой программный автопилот; результаты **не** являются оценкой побед человека.

Исходный симулятор: `scripts/experiment-tower-fights.mjs`. Запуск в GitHub Actions `.github/workflows/tower-experiment.yml`.

## Дополнительная диагностика после первоначальных 52 боёв

Проверка [CI 44049901613](https://github.com/EvasDaeDev/biovshi/actions/runs/44049901613) повторила матрицу из **39 боёв** и запустила ещё **12 прицельных боёв**: четыре сида для каждого из `legs`, `long_legs`, `long_arms`. Это реальные симуляции; 39 повторяют уже использованные исходные условия и **не являются независимой новой выборкой** для статистики баланса.

Результаты контрольной матрицы совпали с предыдущим прогоном: 19 завершений до 75 сек, 20 достижений лимита, 0 ошибок, 0 некорректных координат, 0 пересечений при старте и 0 измеренных проникновений в стены. **Максимальное измеренное динамическое перекрытие корпуса — 0,62 см**; 9 наблюдений перекрытий были ограничены тремя обычными аренами. В 12 дополнительных боссовых боях динамических перекрытий в ежесекундных замерах не обнаружено.

Добавлена подробная диагностика условий рывка (`chargePlan` принимает необязательный объект счётчиков). Отчёты строятся без изменения самих правил рывка. В [CI 44051160030](https://github.com/EvasDaeDev/biovshi/actions/runs/44051160030) для `long_legs` при 5 замерах в секунду получилось **100 наблюдений «цель слишком близко»** и только **2 наблюдения в допустимом диапазоне расстояний**: одно с неподходящим углом и одно с недостаточным числом конечностей. Это наблюдения во времени, **не 102 отдельные попытки рывка**. Четыре боя прошли без рывков, но с полноценными попаданиями и без ошибок.

Экспериментальный разворот перед рывком в [CI 44050679079](https://github.com/EvasDaeDev/biovshi/actions/runs/44050679079) не изменил ни частоту рывков, ни боевые результаты и был отменён. **Вывод:** при этих условиях длинный многоногий предпочитает ближний бой и удары ногами; отсутствие рывка не означает неисправность траектории. Искусственно вытягивать босса на расстояние для рывка пока не требуется.

Для защиты от новых ошибок геометрии в headless-симулятор добавлен автоматический порог глубины перекрытия **2 см**: `maxBodyOverlapCm > 2` теперь приводит к неуспешному результату тестов. Порог относится к проверке корпуса на дискретных срезах **раз в секунду** и не гарантирует отсутствие более коротких коллизий между измерениями.

## Длительные схватки: проверка двух способов управления

В [CI 44053863360](https://github.com/EvasDaeDev/biovshi/actions/runs/44053863360) проведены **28 новых автосхваток до 120 секунд**: семь обычных арен, по два одинаковых начальных сида и две политики игрока. Добавлен секундный сбор количества вооружённых противников, расстояния до ближайшей цели, атак игрока, попаданий и поведения поиска/бегства. Эти прогоны используют **полный игровой цикл и физику**, но не воспроизводят ручное управление.

| Политика игрока | Испытаний | Завершены за 120 с | Победы игрока | Достигли лимита |
|---|---:|---:|---:|---:|
| Прямое сближение до 36 см | 14 | 14 | 0 | 0 |
| Обход цели на ~55 см | 14 | 8 | 5 | 6 |

В шести незавершённых боях обходного автопилота оставались **живые вооружённые противники**. Последние десять секунд классифицированы как `attacks-without-hits` (5 случаев) или `no-attack-opportunities` (1). Среднее расстояние игрока до ближайшего врага в этом окне — примерно **43–59 см**. Эти расстояния не означают, что игрок всё время находился вне любой досягаемости, но его автоматическая траектория не обеспечила завершающих попаданий.

Вывод: **сам лимит времени не доказывает застревание алгоритмов движения**. В симуляциях с прямым сближением все 14 боёв завершились, хотя все — поражением агрессивного автопилота. Пока нет основания менять боевой ИИ, повышать агрессию врагов или принудительно прекращать затянувшиеся бои; это существенно изменило бы баланс и наказало осторожную игру человека.

В ходе проверки не было ошибок исполнения, некорректных координат, стартовых наложений или проникновений в препятствия. Максимальная глубина перекрытия корпуса на секундных замерах составляла **0,69 см** в режиме прямого сближения и **0,62 см** при обходе — ниже автоматического порога 2 см.

Новые инструменты:
- `scripts/tower-battle-analysis.mjs` — чистые функции захвата состояния и классификации длинных боёв
- `tests/tower-battle-analysis.test.js` — тесты причин затяжного боя
- `scripts/compare-tower-fights.mjs` — генерация сравнения двух политик по одинаковым исходным сидам
- `artifacts/tower-fight-comparison.md` — читаемый отчёт, выгружается CI вместе с сырыми JSON

Замечание: одинаковый начальный сид **не гарантирует одинаковую дальнейшую последовательность случайных событий**, поскольку действия игрока меняют ветви ИИ и число обращений к ГСЧ. Результат показывает влияние двух конкретных автопилотов, не процент побед живых игроков.

## Приоритеты следующих проверок

1. **Глубина динамических перекрытий:** собирать максимальное проникновение тел, а не только количество кадров с наложением.
2. **Рывок `long_legs`:** диагностировать, почему не строится `chargePlan`, на нескольких стартовых позициях. Подтвердить, что это не следствие ограничений конкретной «Колоннады».
3. **Длительные схватки:** разнести причины по категориям: игрок держит дистанцию, низкая мобильность из-за ампутаций, отсутствие доступных атак, препятствия.
4. **Ручной баланс:** протестировать живое управление в Telegram WebView — победы автопилота нельзя считать прогнозом сложности для игрока.
5. **Повторяемость и оптимизация:** продлить отдельные прогоны, измерить время CPU на разных количествах участников, проверить FPS на устройствах.

## Воспроизведение

Команды при наличии полной копии репозитория и зависимостей:

```bash
npm ci
npm test
npm run build
node scripts/experiment-tower-fights.mjs --seeds=1 --limit=35 --policy=approach --out=artifacts/tower-approach.json
node scripts/experiment-tower-fights.mjs --seeds=3 --limit=75 --policy=orbit --out=artifacts/tower-orbit.json
```

GitHub Actions в прогоне B подтвердил прохождение `npm test`, `npm run build` и этапа симуляций; подробный файл `tower-fights.json` доступен среди artifacts соответствующего запуска.

**Важное ограничение:** бои создаются с заранее определёнными составами для покрытия геометрии и анатомий; это не замер вероятностей генератора этажей. Для боёв использован простой автопилот, а не человек.
