# БиоВши

Арена PixiJS/WebGL с четырьмя биороботами и локальным тотализатором на виртуальные фишки.
Проект выделен из `biovshi-gladiators-totalizator (10).html`. Правила, геометрия,
балансы и ключ `biovshi.local-totalizator.v1` сохранены.

## Быстрый запуск

Нужен Node.js 22.12 или новее.

```bash
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite. Для разработки используйте этот сервер.
Для запуска двойным щелчком используйте готовый `dist/biovshi.html`.

```bash
npm test             # Правила повреждений, завершение боя, выплаты
npm run build        # Сайт в dist/, для статического хостинга
npm run standalone   # dist/biovshi.html, можно открыть двойным щелчком
npm run preview      # Проверка обычной сборки через локальный сервер
```

Если нужны обе сборки, выполняйте `build` перед `standalone`: обычная сборка очищает
`dist/`. В архиве уже есть готовый `dist/biovshi.html`.

## Публикация на GitHub Pages

1. Загрузите **содержимое** папки `biovshi/` в корень репозитория. Рядом должны
   находиться `index.html`, `package.json`, `src/`, `styles/` и `.github/`.
   Не создавайте дополнительный уровень `biovshi/` внутри репозитория.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Отправьте изменения в `main` или `master`. Файл `.github/workflows/pages.yml`
   установит зависимости, выполнит тесты, соберёт проект и опубликует `dist/`.
   Для другой основной ветки измените список `branches` в этом файле.
4. Дождитесь успешного workflow во вкладке **Actions**, затем откройте адрес Pages.
   Можно вручную запустить workflow кнопкой **Run workflow**.

`base: './'` в Vite сохраняет относительные ссылки в сборке, поэтому имя
репозитория прописывать не нужно. Пути в исходном `index.html` также относительные:
они не уводят запросы с `/имя-репозитория/` в корень домена.

Если используется публикация готовых файлов через **Deploy from a branch**,
публикуйте содержимое `dist/` после `npm run build`. В текущей версии исходные
ES-модули тоже могут работать на статическом сервере, но для ресурсов из
`public/` и дальнейшего развития используйте сборку.

При загрузке через веб-интерфейс проверьте, что `.github/workflows/pages.yml`
попал в репозиторий: скрытые папки некоторые файловые менеджеры не показывают.
Если после обновления видна старая версия, обновите страницу с Ctrl+F5.

## Состояние и зависимости

`main.js` запускает игру. `game/initialize.js` сохраняет порядок создания слоёв,
объектов и обработчиков из исходной версии. Общие данные одной арены находятся
в `game/state.js` (`ctx`); импорт модулей сам по себе игру не запускает.

У каждого робота отдельный внутренний `robotState`. Вспомогательные функции
получают его первым аргументом; внешний API (`tick`, `paint`, `damage` и геттеры)
сохранён. Это позволяет менять анатомию и движение в отдельных файлах.
`robot.js` пока содержит создание SVG-узлов, состояния и сборку API: его можно
дальше дробить по мере появления новых типов роботов.

Взаимные импорты части систем сохранены при переносе общей логики. Функции не
вызываются при импорте: инициализация выполняется только из `initializeGame()`.
Не добавляйте обращения к DOM или симуляции на верхнем уровне этих модулей.

Прежний режим охотника и захвата удалён из игрового цикла и исходников.
Общие анимации и кинематика, используемые текущими сценами, сохранены.

Симуляция использует сантиметры, секунды и радианы в расчётах; углы в CONFIG
подписаны в градусах. Частота расчёта — 60 шагов/с, отрисовки — до 30 кадров/с.

## Текстуры

1. Положите оригинал в `_src/texture-inputs/textures/arena/` и выполните `npm run textures`.
2. В `src/assets/manifest.js` задайте, например:

```js
textures: {
  arenaFloor: 'assets/textures/arena/floor.webp',
  obstacle: 'assets/textures/arena/wall_02.webp', // Полоса стен внутрь препятствий.
},
```

Включена текстура `assets/textures/arena/floor_01.webp`. Вся картинка повторяется
каждые 100 × 100 см, независимо от масштаба камеры. При загрузке текстура пола
однократно тонируется в текущую вычисленную заливку пола (сейчас `#010409`),
сохраняя перепады яркости и прозрачность исходника. Сила смешивания задаётся
в `src/config.js`, в `rendering.floorTintStrength`: `0` — исходная текстура,
`1` — полное тонирование, текущее значение `0.76` — тёмная серо-зелёная плитка. Тесты проверяют
режимы отдельно от этой настройки, поэтому её можно менять без правки тестов.
Результат — обычная PNG
в SVG-узоре, без покадрового Canvas или SVG-фильтра. До загрузки и при ошибке
файла остаётся исходная заливка. Координатная сетка и метровые подписи
выключены через `CONFIG.rendering.coordinateGrid`.

SVG-узор повторяется каждые 100 см. Его параметры находятся в
`src/render/textures.js`. Текстуры не меняют столкновения. `null` сохраняет
прежнюю заливку. Папка `textures/robots/` подготовлена для будущих покрытий
роботов; автоматическое наложение на роботов пока не включено.

## Звуки

Добавьте файлы в `public/assets/sounds/` и укажите пути в том же манифесте:

```js
sounds: {
  hit: 'assets/sounds/combat/hit.ogg',
  'segment-broken': 'assets/sounds/combat/sever.ogg',
  'robot-immobilized': 'assets/sounds/combat/disabled.ogg',
  'combat-end': 'assets/sounds/interface/victory.ogg',
},
```

По умолчанию пути равны `null`: новые звуки не добавлены. Модуль получает
события через `game/event-bus.js`. Начальная громкость — 0.5, одновременно до
8 звуков. `createAudio()` возвращает `setVolume`, `setMuted`, `stopAll`, `dispose`.
Воспроизведение начинается после взаимодействия пользователя; отказ браузера
в воспроизведении не прерывает игру. Кнопки громкости пока не добавлены.
ИИ использует зрение и память последнего видимого противника. Неиспользуемый
слух удалён; звуки шагов воспроизводятся по событиям постановки ног.

В одиночную HTML-сборку автоматически встраиваются файлы из `public/assets/`:
PNG, JPEG, WebP, SVG, OGG, MP3, WAV и WOFF2. В коде обращайтесь к ним через
`assetUrl()` из манифеста. Для других форматов расширьте MIME-таблицу сборщика.
Пути непосредственно в CSS и HTML не встраиваются этим механизмом.

## Сохранения

Сессия хранится в localStorage браузера. Адрес локального сервера, опубликованный
сайт и локальный HTML могут иметь разные хранилища. Для продолжения старой сессии
сохраните прежний адрес запуска; автоматический перенос между адресами не добавлен.

## Производительность на планшетах

В панели управления есть выбор **Графика: Авто / Полная / Лёгкая** и счётчик FPS.
Счётчик показывает частоту новых игровых кадров; текущий предел — 30 кадров/с.
Частота расчёта боя остаётся 60 шагов/с в обоих режимах.

В режиме «Авто» устройства с сенсорным указателем, включая iPad с режимом
настольного браузера, получают лёгкую графику. Выбор можно изменить вручную;
он сохраняется отдельно от ставок в `biovshi.graphics.v1`.

В лёгком режиме сохраняются роботы, цветные буквы, маски темноты,
перекрытие света препятствиями, масло, вспышки отрыва и объявления. Уменьшаются
число лучей для рисования света и частота его обновления до 15 раз/с; отключаются
размывающие фильтры стационарного света. Радиальные пятна света и тени сохраняются.
Детальность зрения ИИ не меняется. Переключение не перезапускает раунд.

Общие оптимизации работают и на компьютере:

- поверхность SVG-фильтра обводки ограничена самим роботом;
- один контур ближнего света используется сразу для маски и подсветки;
- неподвижный свет не пересчитывается;
- камера меняет viewBox вместе с отрисовкой, а не на каждом обновлении экрана;
- телеметрия обновляется до 10 раз/с и сразу при повреждениях;
- скрытые искры не создаются и не рассчитываются;
- завершившие растекание пятна масла больше не обновляют свои атрибуты.

Настройки находятся в `CONFIG.rendering`, профили — в
`src/render/performance.js`, кэш света — в `src/render/lighting.js`.
Для включения искр при последующей разработке задайте `rendering.sparks: true`
и уберите `display:none` у `#tag7hop-sparks` в CSS; настройка применяется при запуске.


## Подготовка текстур: пиксельный стиль

Оригиналы находятся в `_src/texture-inputs/textures/`, готовые текстуры — в
`public/assets/textures/`. Исходный пол сохранён как
`_src/texture-inputs/textures/arena/floor_01.png` (512 × 512).

`npm run textures` автоматически обрабатывает PNG, JPEG и WebP из исходной
папки, сохраняя структуру подпапок: максимальная сторона 256 пикселей,
уменьшение ближайшим соседом, выходной формат WebP lossless (без потерь при
кодировании уменьшенного изображения). Меньшие изображения не увеличиваются.
Не используйте два исходника с одинаковым именем и разными расширениями
в одной папке: у них был бы общий выходной `.webp`.

Обработка автоматически запускается перед `npm run build` и
`npm run standalone`. В GitHub Pages это выполняется тем же workflow.
В манифесте указывайте готовый файл, например
`assets/textures/arena/floor_01.webp`. Для локальной разработки после замены
исходника выполните `npm run textures`.

Настройки в `src/config.js`:

```js
textureMaxSize: 256,
texturePixelated: true,
floorTintStrength: 0.76,
```

Canvas при загрузке также ограничен 256 пикселями, сглаживание выключено;
SVG использует `image-rendering: pixelated`. При приближении сохраняются
резкие границы пикселей. Тонирование вычисляется один раз, не в игровом цикле.
Размер повторения на арене остаётся 1 × 1 метр. Цвет и сила тонирования задаются в `CONFIG.rendering`.

Пол: 142 266 байт PNG → 36 612 байт WebP, примерно на 74% меньше. Декодированная
площадь текстуры сократилась в четыре раза (512² → 256²). Результаты других
изображений будут зависеть от их содержимого.

## Внешняя стена арены

Исходник `_src/texture-inputs/textures/arena/wall_01.png` обрабатывается общим
скриптом в `public/assets/textures/arena/wall_01.webp` (128 × 64, 8 046 байт).
Меньший исходник не увеличивается до 256. Стена сохраняет свои исходные цвета.

Статичный SVG-слой расположен снаружи периметра. Внутренняя кромка совпадает
с границей пола; нижняя строка изображения смотрит на пол. Размер тайла —
100 см вдоль внутренней кромки и 30 см наружу. Текстурные координаты идут
непрерывно через прямые грани и скошенные углы; на замыкании периметра
последний повтор подрезается. Углы соединены без геометрических зазоров.

Площадь игры, расстановка, столкновения и координаты 0…700 см не изменены.
Общий обзор расширен до 776 × 776 см: 700 см пола, по 30 см стены и по 8 см
запаса. Камера при приближении учитывает внешнюю полосу. Таймер вынесен из
слоя, обрезанного по полу, и остаётся поверх арены.

Параметры в `src/config.js`, раздел `arena`:

```js
wallThicknessCm: 30,
wallTileLengthCm: 100,
wallViewMarginCm: 8,
```

Геометрия и развёртка — `src/render/wall-geometry.js`, отрисовка —
`src/render/walls.js`. Слой состоит из 16 статичных треугольников с общей
текстурой; пересчётов в игровом цикле и новых SVG-фильтров нет.

## Свет операционной и стены препятствий

Стационарное освещение задаётся `light.ambientColor` в `src/config.js`
(`#8b9e91`), с интенсивностью `light.ambientIntensity: 0.55`. Цвет лучей и
ближнего света роботов — `--night-light: #d3cead` в `styles/interface.css`,
приглушённый грязновато-тёплый оттенок. Почти чёрные отпечатки
используют отдельный `--night-trail: #080604`, без свечения. Цветная окантовка
препятствий и периметра отключена: `arena.outlineColor: 'none'`.

`wall_02.png` сохранена в `_src/texture-inputs/textures/arena/`; при сборке создаётся
`wall_02.webp` (128 × 64, lossless). Параметр `ASSETS.textures.obstacle`
указывает на эту текстуру. Она оборачивает каждое препятствие с повтором
100 см вдоль границы и шириной 30 см внутрь. Нижний край изображения совпадает
с полом, углы соединяются общей геометрией. На узких треугольниках полоса
ограничивается перед схождением граней; верх изображения подрезается,
а масштаб сохраняется. Столкновения и размер препятствий остаются прежними.
Добавлены 44 статичных треугольника, без пересчёта в игровом цикле.

Изображение `wall_02` повёрнуто на 180° внутри тайла. Радиус отпечатков
задаётся `trails.radiusCm: 2.925` (увеличен ещё в 1.5 раза от 1.95 см).
Основная жидкость использует спрайты `liquids.png`. Резервный цвет при ошибке
загрузки — оттенки вокруг тёмного бордового `#380607`, `oil.hueSpreadDeg: 12`.
За `oil.drySec: 18` секунд жидкость становится буро-чёрной и менее насыщенной.

Деформация пола и координатной сетки от попаданий удалена. Пол остаётся
статичным во всех режимах; короткие кольца попаданий и вспышки отрыва сохранены.

## Растровые роботы A–D

Атласы находятся в `public/assets/textures/robots/`:

| Робот | Атлас | Настройка |
| --- | --- | --- |
| A | `r_01.png` | `ASSETS.textures.robotA` |
| B | `r_02.png` | `ASSETS.textures.robotB` |
| C | `r_03.png` | `ASSETS.textures.robotC` |
| D | `r_04.png` | `ASSETS.textures.robotD` |

Это PNG с прозрачностью, 256 × 256 пикселей, 4 × 4 ячейки по 64 пикселя.
У всех четырёх атласов общая разметка:

| Ряд | Столбец 1 | Столбец 2 | Столбец 3 | Столбец 4 |
| --- | --- | --- | --- | --- |
| 1 | Голова | Грудь с плечами | Спина 1 | Спина 2 |
| 2 | Таз с поясом | Резерв | Резерв | Резерв |
| 3 | Левое плечо | Левое предплечье | Правое плечо | Правое предплечье |
| 4 | Левое бедро | Левая голень | Правое бедро | Правая голень |

Привязки находятся в `src/render/robot-skin.js`, объект `ROBOT_PARTS`.
Для конечностей основание слева, конец справа; стороны соответствуют самому
роботу (`-1` — левая). Ось суставов проходит по Y=32, обычно X=8…56.
Для всех рук и ног используются исходные точки X=8…56, без дополнительного
увеличения бёдер. Грудь использует X=30…54, остальные сегменты корпуса — X=8…32; каждый сегмент следует
точно за концами своей кости, без удлинения груди и таза. Грудь и таз содержат пояса,
отдельных изображений для них нет. Голова вращается и выдвигается при ударе.
Все четыре сегмента корпуса `spine-0`…`spine-3`, включая грудь с плечевым
поясом и таз с тазовым поясом, расширены поперёк оси кости на треть
(`widthScale: 4/3`). Это только масштаб изображений: длина сегментов,
координаты суставов и места крепления рук и ног остаются прежними.
В загруженных файлах лицо направлено влево. Привязки головы — X=33 → X=8,
поэтому центр её оси находится на X=20.5. Все оси проходят по Y=32.
Грудной сегмент целиком сдвинут на 22 пикселя вправо по атласу: 8…32 → 30…54.
Длина его оси остаётся 24 пикселя, поэтому масштаб текстуры груди сохранён.

Каждая ячейка показана через отдельное SVG-окно одного общего атласа;
изображения следуют за существующими суставами, не меняя столкновения и ИИ.
После загрузки скрываются прежние линии и кружки соответствующего робота,
включая дополнительные векторные украшения B и C; при ошибке загрузки
они возвращаются. Сохраняются исходные цвета PNG, индивидуальные цвета букв,
освещение и победное переливание (тонирование включается только в финале).
Отсечённые части сохраняют текстуру и неподвижный снимок видимой позы,
включая положение во время прыжка. Атлас также встраивается в автономный HTML.

Цветных обводок и индикации состояния цветом/свечением на арене нет.
Повреждения отображаются в карточках. Буквы A–D используют общий с карточками
массив `ROBOT_COLORS` из `src/utils/colors.js` и не меняются при повреждениях
или победе. Для векторного резерва используется постоянный нейтральный цвет.
Победное переливание текстуры сохранено. Прозрачность цветного конуса зрения
увеличена вдвое: непрозрачность остановок градиента 0.10 / 0.05 / 0.

## Мрачная операционная

- Пол: `rendering.floorTintColor: '#26312b'`, `floorTintStrength: 0.76`.
- Стены периметра и препятствий: `wallTintColor: '#18231f'`, `wallTintStrength: 0.8`.
- Тинт применяется один раз при загрузке, с сохранением зерна, прозрачности,
  метрового повтора и поворота `wall_02`. Исходные файлы не перекрашиваются.
  Значение силы `0` возвращает оригинал.
- Темнота серо-зелёная (`#090f0c`), `light.darknessOpacity: 0.92`.
- Поле зрения показано одним чётким конусом в обоих режимах графики.
  Смягчение боковых краёв удалено; затухание вдоль луча и тени препятствий сохранены.
- Источники изредка независимо тускнеют на 15–20% на 0.18–0.31 секунды.
  `light.flickerDepth` регулирует глубину. Часы эффекта используют время боя,
  не потребляют игровой генератор случайных чисел и замирают на паузе.
  При `prefers-reduced-motion` просадки отключены.
- Стартовые кольца скрыты во время боя; центральная красная окружность удалена. По краям
  игрового окна добавлена слабая виньетка, независимая от камеры.
- Объявления и короткие кольца попаданий приглушены; вспышка отрыва,
  цветные буквы и победное переливание сохранены.

Освещение влияет на картинку: радиус зрения, столкновения,
движение, урон и тотализатор используют прежние правила.

## Спрайты жидкости и мягкие пятна

`ASSETS.textures.liquids` указывает на `public/assets/textures/arena/liquids.png`:
16 спрайтов в сетке 4 × 4, ячейка 64 × 64 пикселя. Каждая капля получает
свой спрайт и поворот из отдельного визуального хеша, без расходования
игрового генератора случайных чисел. Окно SVG обрезает только выбранную
ячейку; при растекании её размер растёт вместе с каплей.
Капающая жидкость появляется с удвоенными радиусом и диаметром:
`oil.dropSizeScale: 2`. Крупное пятно при остановке робота сохраняет свой
прежний исходный размер. Число случайных выборок симуляции не изменено.

Три версии атласа для высыхания готовятся один раз при загрузке, с сохранением
прозрачности. `oil.spriteDryColor` и `spriteDryStrength` задают буро-чёрный
финальный оттенок. При ошибке загрузки показывается резервная цветная капля.

Под торсом каждого робота находится мягкий чёрный эллипс:
`robot.shadowOpacity: 0.5`, `robot.shadowPadding: 1.2`. Границы определяются
по четырём видимым сегментам корпуса, включая пояса, и расширяются на 20%.
Голова и конечности не входят в размер пятна. Тень следует положению и повороту
тела на земле; при потере сегментов уменьшается. Полная ячейка текстуры
используется как консервативная граница растрового сегмента.

Вокруг каждого препятствия добавлен мягкий световой круг. Его диаметр равен
максимальному расстоянию между вершинами препятствия плюс
`light.obstacleLightExtraDiameterCm: 100`. Цвет берётся из `light.ambientColor`,
яркость регулируется `obstacleLightOpacity` и `obstacleLightReveal`.
Пятно лежит под препятствием, а отдельная маска приоткрывает темноту вокруг.
Оно сохраняется после сброса раунда. Все новые мягкие края реализованы
радиальными градиентами без дополнительных фильтров размытия.

## Ретро-акценты попаданий

Подтверждённое попадание вызывает короткую ступенчатую бело-жёлтую вспышку
в точке контакта и направленный от атакующего веер красных пиксельных брызг.
Отрыв сегмента даёт более крупную вспышку и более длинный/плотный разлёт.
Отказанный контакт во время неуязвимости эффект не запускает. Это отдельный
акцент удара; состояние повреждений по-прежнему отображается в карточках.

Настройки в `CONFIG.effects`: `hitEffects`, `hitPoolLimit: 8`,
`hitParticles: 8`, `severParticles: 14`, `hitLifeSec: 0.38`, `hitFlashSec: 0.09`.
Усиленный эффект живёт примерно 0.51 секунды. В лёгком режиме число частиц
уменьшается вдвое. Узлы создаются при первом попадании и затем переиспользуются;
лимит пула защищает от накопления. На паузе время эффекта замирает, сброс
раунда скрывает все акценты. Фильтров размытия, полноэкранных вспышек и
дополнительных вызовов игрового генератора случайных чисел нет.

Свежие следы теперь имеют `trails.opacity: 0.753` вместо прежних 0.506:
их прозрачность уменьшена на 50% (0.494 → 0.247). Старые следы по-прежнему
полностью исчезают за `trails.fadeSec` секунд. Размер следов не менялся.

## Рендер и диагностика

Основной рендер — PixiJS 8 / WebGL. Пол, декали, стены и стационарный свет
подготавливаются один раз. Сегменты пациентов и жидкость — спрайты с общими
источниками текстур; конечности, следы и эффекты обновляются только при изменении.
SVG остаётся скрытым описанием поз и резервным рендером при отсутствии WebGL.
Его изображение не сериализуется и не загружается в GPU каждый кадр.
Симуляция по-прежнему идёт фиксированными шагами 1/60 с; у Pixi нет второго ticker.

Откройте «Настройки» шестерёнкой справа сверху: в диагностике указан активный
рендер и CPU-время симуляции, подготовки кадра, WebGL и карточек. WebGL-замер
показывает отправку команд, а не фактическое время исполнения GPU. Переключатель
«Телеметрия» прекращает обновление и отображение карточек, сохраняя размеры арены
для корректного сравнения FPS. `?telemetry=0` выключает её при старте;
`?renderer=svg` оставляет старый рендер для A/B-сравнения.

`npm run profile:ui` сравнивает минуту одного боя с карточками и без них, проверяет
идентичность симуляции и выводит время JS, число изменений и размер DOM карточек
по десятисекундным отрезкам. Это Node/JSDOM, без браузерного layout, GPU и Safari:
он не заменяет минутный прогон на iPhone/iPad.

Постобработка арены настроена по эскизу Photoshop: Unsharp Mask 80%, радиус 1 px,
Film Grain 1, искажение −7, красный/голубой −35, синий/жёлтый +29, виньетка −76
с серединой 50. Значения находятся в `CONFIG.postEffects`; нелинейные шкалы
Lens Correction приближённо переведены в параметры шейдера. Пять эффектов
выполняются одним проходом, относительно окна арены, включая буквы и таймер.
Старая CSS-виньетка при этом не накладывается повторно.

Под «Телеметрия» находится общий переключатель «Постэффекты». Он сохраняет выбор
между запусками и работает на паузе. Выключение полностью убирает проход
постобработки. Карточки, кнопки, физика, ИИ и зрение не зависят от переключателя.
В резервном SVG-рендере постэффекты недоступны.

## Настройки и карточки пациентов

Шестерёнка в правом верхнем углу открывает окно с телеметрией, постэффектами
и последними активными замерами производительности. Открытие приостанавливает
бой и появление пациентов; закрытие возвращает прежнее состояние паузы и скорость.
Закрыть окно можно крестиком, Escape или нажатием на фон. Строка правил под ареной удалена.

Окно арены прямоугольное и заполняет центральную колонку по ширине. Его высота
учитывает высоту экрана. При общем виде квадратная арена вписана внутрь по
меньшей стороне без растяжения; физический периметр и координаты не меняются.

В карточках используются исходные атласы r_01…r_04 и нейтральная поза с теми же
координатами сегментов. Здоровые части полноцветные, предупреждение оранжевое,
критическое состояние красное, отсутствующие части серые и дополнительно затемнены на 50%. Цветные варианты
подготавливаются один раз, а миниатюра перерисовывается только при смене состояния
сегмента. Отдельная симуляция или цикл анимации для карточек не создаётся.

Карточки пациентов и игроков имеют общий фиксированный размер 280 × 164 px
(`--card-width`, `--card-height` в `styles/interface.css`). Выбор качества графики
перенесён в окно настроек; переключатель и его сохранённое значение используются прежние.

Кнопка с монитором справа снизу в поле включает развёрнутый вид: обе боковые
панели скрываются, окно арены занимает доступную область браузера под верхней
панелью. Повторное нажатие или Escape возвращают обычный вид. Бой, пауза и
скорость времени при этом не меняются; выбранное отключение телеметрии сохраняется.
В скрытых карточках миниатюры не перерисовываются.


## Процедурная, покровители и история пола

Бионические протезы дают за каждый сохранившийся сегмент **+3% к исходным очкам
скорости и силы и −2% к очкам маневренности** (`CONFIG.prosthetics`). Учитываются
11 заменяемых сегментов: конечности и три разрушаемых сегмента позвоночника.
Поправки складываются, базовые очки не меняются; дробные эффективные очки
плавно пересчитываются по существующим формулам, с прежними потолками эффектов.
Отрыв протеза убирает его бонус и штраф до восстановления, смерть сбрасывает
протезы. Карточки показывают итоговые очки, синяя рамка обозначает влияние
бионики. Хинт по наведению, фокусу или нажатию раскрывает исходное значение,
число сегментов, поправку и результат. В процедурной и подготовке башни
селекторы меняют исходные целые очки; хинты и сводка учитывают протезы.

При открытии игры сразу начинается бой без ставок; сохранённые балансы и джекпот не расходуются. После итогов «Следующий раунд» ведёт к ставкам, а «Процедурная» — к настройке пациентов. Скорость, сила и маневренность имеют базовые 3 очка; допускается только один перенос: перестановка 2 / 3 / 4. Скорость движения и поворота получают множители 80 / 100 / 120% поверх действующих глобальных настроек и штрафов повреждений. Сила задаёт вероятность мощного удара на 2 HP: 0 / 15 / 30%; обычный удар снимает 1 HP. Подтверждённый мощный удар показывает оранжевое «Crit!» на 0,2 секунды. Пациент может одновременно атаковать до двух разных противников разными руками или ногами, если обе цели физически досягаемы. Каждая конечность наносит один отдельный удар по одной цели; две атаки по одному пациенту в одном цикле не назначаются. Попадания, критические удары и потеря атакующей конечности проверяются отдельно для каждой атаки. Прыжок сохраняет единственную цель. Правило действует во всех режимах для игрока и ИИ.

Четыре головных убора берутся из `public/assets/textures/robots/decor/head/1.png` … `4.png`. Установка оплачивается выбранным игроком: пустой слот стоит 10 фишек, замена — минимум предыдущая цена +10% с округлением вверх. Можно указать большую цену. Покупка полностью списывается без возврата и не входит в банк ставок. При потере головы слот немедленно освобождается, шапка остаётся на оторванной голове. Проигравшие теряют все украшения; у победителя сохраняются уцелевшие. Настройки и покупки локальны для текущей игры в этом браузере.

Чистый пол собирается один раз в непрозрачное изображение 1024 × 1024. Перед переходом из итогов в следующий раунд к нему добавляются останки, потерянный декор и жидкости в конечных мировых координатах. Только новый слой теряет 50% насыщенности и 50% контраста относительно соответствующих пикселей пола. Старые следы не обрабатываются повторно. После запекания отдельные объекты удаляются. Освещение, буквы пациентов, интерфейс, постэффекты и победитель не запекаются. Текстура сохраняется в IndexedDB; при недоступном хранилище действует до закрытия страницы. Кнопка «Уборка в помещении» в процедурной восстанавливает чистый пол. Новая игра также очищает пол.


Покровитель пациента — игрок с максимальной суммой всех покупок для него за текущую игру. Потеря декора и поражение пациента не обнуляют вложения. При равенстве сохраняется действующий покровитель; пока вложений нет, настройка свободна. В процедурной выбранный игрок может менять характеристики только своих подопечных. Нажатие или наведение на имя покровителя открывает перечень вложений всех игроков. При переносе старых сохранений учитываются известные сохранившиеся украшения; история ранее потерянных покупок в старом формате не записывалась.

В ставках можно выбрать операционную 7 × 7 м с препятствиями, правильный восьмиугольный ринг 4 × 4 м без препятствий или «Кольцо»: шестнадцатиугольную арену диаметром 6 м с круглым препятствием диаметром 2 м в центре. В башне все три арены выбираются случайно с равной вероятностью. Схемы арен показаны в раскрывающемся меню. Настройки, декор и балансы общие; полы сохраняются раздельно. Камера следует за живыми пациентами без упора в периметр, учитывая пропорции окна: запас 2 м по горизонтали и 1 м по вертикали, когда это возможно без отдаления дальше масштаба ×1. Журнал в правом верхнем углу хранит последние 10 событий, не использует боевой генератор случайных чисел и не запекается на пол.

Исходные PSD, референсы и неиспользуемые аудиозаписи хранятся в `_src/` вне сборки. Правила выплаты джекпота и полного отката отменённого боя описаны в `docs/BETTING.md`.

Накопленная травма: параметры, сравнительные прогоны и команды воспроизведения находятся в [docs/TRAUMA_EXPERIMENT.md](docs/TRAUMA_EXPERIMENT.md). Порог потери сознания — 24, вес повреждений головы — ×1,5.
