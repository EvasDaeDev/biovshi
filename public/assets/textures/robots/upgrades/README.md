# Атласы для модификаций протезов

**Статус:** это точные побайтовые копии `public/assets/textures/robots/ar_01.png` и соответствующего `ar_01.psd`. Пока ты их не перерисуешь, все варианты выглядят одинаково. **Игра пока не выбирает эти новые атласы автоматически** — подключение вариантов будет отдельным этапом после готовности рисунков.

## Как устроен атлас

- Размер каждого PNG: **256 × 256 px**, сетка **4 × 4** по **64 × 64 px**. Прозрачность сохранить.
- Для каждого имени есть `*.png` (готовый атлас для игры) и `*.psd` (редактируемый исходник). После правки PSD экспортировать PNG **с тем же именем**.
- При изменении конкретной части тела сохраняй общую позицию сегмента внутри его ячейки, масштаб и ось сустава **y = 32 px**. Не сдвигай ячейки и не изменяй число пикселей между точками крепления.
- Рисуем **полную замену текстуры сегмента**, не навесную наклейку. Нужные части можно полностью перерисовать; остальные ячейки по возможности оставить исходными.
- Стилистика БиоВшей: грязный ретро-медицинский/индустриальный биопанк, потёртый металл, приглушённые цвета, без яркого неона и анимешных контуров.

| Строка | Столбец 1 | Столбец 2 | Столбец 3 | Столбец 4 |

## Важные ограничения перед подключением

- **Хирургия** привязана к *одному конкретному сегменту*, поэтому из атласа операции должна выбираться только ячейка этого сегмента. Для руки и ноги подготовлены варианты обеих сторон и обоих участков.
- **Мутации** уже существуют как игровые эффекты и могут сосуществовать с хирургией. Эти 18 файлов — отдельные художественные исходники, а не 18 полных скинов пациента. Для итогового рендера нужно будет определить, какая модификация отвечает за каждую ячейку; если несколько улучшений претендуют на одну часть тела, потребуется отдельное правило приоритета или композиция.
- **Синергии** трёх семейств не требуют собственных атласов: их внешний вид должен составляться из установленных модификаций.
- Сейчас никакие пути в `src/assets/manifest.js` или игровой код не меняются: по готовым PNG подключим выбор замены по ключу сегмента и сохранение изменённой текстуры на оторванных частях.
- Старый `ar_01.png` / `ar_01.psd` остаётся неизменным. Все заготовки происходят из него и не изменяют другие режимы игры.

## Контроль готовности

1. В каждом PNG 256 × 256, 4 × 4 сетка, RGBA/прозрачность сохранены.
2. Центры шарниров и длины соответствуют исходнику; конечности не выходят за границы своей ячейки.
3. Изменение видно в игровом масштабе сверху, а не только при увеличении.
4. PSD и PNG содержат одну и ту же актуальную версию изображения.
